# 演示与技术讲解提示

## 三分钟演示

1. `npm ci`、`npm run build`、`npm start`，打开 http://127.0.0.1:3000。
2. 解释总资产 10 万元为何包含 2 万元现金，指出 A01 40%、科技 60% 的两项提醒。
3. 卖 A01 100 股，指出现金变为 3 万元，30% / 50% 等于阈值，因此不提醒。
4. 买 A02 100 股，指出连续操作后现金 2.5 万元、A02 500 股、科技 55%，行业再次超限。
5. 输入不合法数量，或尝试买超出余额的数量，解释后端拒绝且上次有效结果保持不变。
6. 命名并保存，刷新页面、到方案列表重开；停止服务再启动后重开一次。
7. 新建模拟，展示原始持仓与现金仍未改变。

## 应能解释的六个问题

**为什么用整数分？** 直接用浮点元计算可能出现十进制误差；后端先严格解析为整数分并检查安全范围，展示时再转回字符串。

**为什么不是用显示百分比判断超限？** 显示会四舍五入，30.004% 可能显示 30.00%。判定用 BigInt 交叉相乘，独立于展示。

**如何保证失败操作不影响已有模拟？** 后端从原始组合拷贝后重放整个操作列表，失败直接拒绝；前端只在完整成功后更新当前操作与结果。

**为什么保存快照和操作？** 既能复算又能解释过程；只存当前文件引用，未来改价格可能导致已保存方案漂移；只存结果不便核对计算来源。

**为什么需要后端？** 即使绕过页面直接发请求，余额、持仓、数量和阈值仍必须一致校验，保存不能信任客户端伪造的金额。

**AI 做了什么，你如何检查？** 据实说明使用 Codex 生成方案、代码、测试和文档；打开 VERIFY.md，展示题目数字断言、真实 SQLite 重开、断网问题的红灯/修复及截图。提交前请自己至少完整演示一遍，确认能解释采用的设计。

## 关键代码入口

- `server/domain.ts`：整数分、占比和顺序模拟。

- `server/store.ts`：快照与操作持久化。
- `client/App.tsx`：有效结果更新、保存、只读重开与未保存提示。
- `tests/domain.test.ts`、`tests/api.test.ts`：题目用例和精度/持久化核验。
