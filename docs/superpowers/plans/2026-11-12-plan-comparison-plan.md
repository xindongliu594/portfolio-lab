# Saved Plan Comparison Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation, with final independent review.

**Goal:** 用户已同意加入两份已保存方案的并排对比，直观看到现金、持仓、行业和超限差异。
**Architecture:** 已保存方案页选两份，复用GET /api/plans/:id读取后端按各自快照复算的结果。前端仅按标的代码/行业名对齐并展示，不另算金融数据、不写库。快照完整内容不一致时提示比较依据不同。
**Tech Stack:** 现有React、TypeScript、CSS、Node测试及Playwright，无新依赖。
**Spec:** 用户确认的聊天描述；下列约束为实施时的明确选择。

## Global Constraints
- 在当前codex/portfolio-assessment分支实施；沿用此前本地路径与预览的工作区决定，baseline fb8e534。保留原始PLAN.md。
- 一次恰好比较两份不同ID方案；第三项不可选，取消已有项后可换选。A/B顺序由勾选顺序决定，同名也分开标识。
- 提供资产/现金/持仓数/操作数/提醒数、标的数量市值占比、行业市值占比、具体提醒；不同值轻量标记，不评判哪份更好。
- 全部金额/占比/提醒复用后端结果，无新增金融计算与API。不同快照完整JSON时显示说明及各自快照标识/时间，不将差异断言为调仓导致。
- 对比不覆盖当前草稿或修改保存方案；原有重开确认继续有效；请求失败保留选择，允许重试，不显示半份结果。
- 仅比较保存时输入和最终结果；比较选择与结果不持久化。白蓝简约，窄屏表格内部滚动。

## Review Focus
- 数组顺序不同、某一侧缺少标的/行业时，按键对齐；缺项标为未包含，零股仍展示0。
- 同快照ID但实际价格/规则内容不同，仍必须提示依据不同。
- 网络失败或某方案不存在时，不展示部分/旧结果；重试可恢复。
- 同名/长名及移动宽度下，选择、A/B身份和比较内容可读。
- 切换选择、刷新列表、跨页重开不使旧比较冒充新选择，不改变未保存模拟。
