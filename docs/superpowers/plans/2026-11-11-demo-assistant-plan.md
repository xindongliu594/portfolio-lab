# Demo Assistant Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. 用户明确要求先做本地模拟版，不接真实模型。

**Goal:** 增加可操作的演示建议与多轮对话，始终标识演示模式。
**Architecture:** Express 从操作/保存方案及步骤重算上下文，本地规则生成解读、经simulate验证的卖出草案和限定主题回复；React展示并由用户明确采用新模拟。
**Tech Stack:** 现有 React/TypeScript/Express/SQLite，无网络、模型或依赖新增。

## 约束与取舍
- 导航新增AI助手，页内为辅助建议和对话；持续显示“演示模式 · 本地规则生成”。回复不会冒充真实模型输出。
- 请求context含operations、stepIndex、可选planId/sourcePlanId；planId读取保存快照及操作，sourcePlanId读取保存快照并回放当前草稿操作，两者互斥。所有数值在后端重算，不接收前端估值为依据。
- 草案只将超过标的30%或行业50%的部分转为现金，不预测收益。使用整数分/BigInt和现有simulate验算；无超限或100笔额度不足时不生成交易。
- 回看原始/历史步骤时建议基于相应前缀；用户采用历史草案替换未保存后续操作时明确确认。保存方案采用后创建独立草稿，不修改已保存数据；不自动保存或执行。
- 演示聊天支持集中度、现金、阈值、步骤变化和草案主题；简短追问回溯最近有主题的用户问题，并用受校验topic枚举延续超出历史窗口的追问。当前上下文为事实依据，聊天内容不能覆盖数字；其他主题说明演示能力边界。
- 聊天最多保留6条输入历史，每条不超1000字符，问题不超1000字符；切换数据/步骤重置会话，导航切换在相同上下文时保留。无聊天持久化。
