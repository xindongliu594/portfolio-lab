# 投资组合分析与调仓模拟：设计提案

日期：2026-11-11；状态：待用户审阅，尚未实现。

## 目标及约束
完成附件 VC-FIN-001 / V3.0 所要求的本地全栈原型及交付材料。评审者按 README 启动后可完成“查看组合 → 识别超限 → 顺序买卖模拟 → 前后对比 → 保存 → 重启后重开”。设计与数字正确性优先；不做任务范围外的金融分析、登录、行情 API、真实下单、公网部署。所有行情及持仓来自用户给出的 JSON，禁止用另造的数据替代验收数据。

## 技术选择（AI 提议，非用户已指定）
前端 React + TypeScript + Vite，后端 Node.js 24 + Express + TypeScript；SQLite 使用 Node 内置 node:sqlite。Node v24.15.0 已在本机验证；数据库无需额外安装服务。前端不复制领域计算。共享接口类型，后端返回统一结果。锁定依赖并交付 package-lock.json。开发模式两端启动；另提供构建后单个本地服务启动命令。无须容器或全局工具。

## 页面与交互
单页中文工作台，浅色中性背景、清晰的数据表和低饱和强调色，优先可读性。桌面将组合明细/对比作为主区，操作面板作为辅区；窄屏纵向排列。
- 头部：名称、组合编号、行情快照时间、固定价格/虚构数据说明。
- 资产摘要：总资产、现金、持仓标的数及超限数量；持仓表展示代码、名称、行业、价格、数量、市值、占比；行业分布以进度条及具体百分比展示，现金单独列示。
- 模拟：选择标的、买/卖方向、输入数量并添加操作，操作列表显示顺序；每次提交后以后端结果更新页面。可放弃当前草稿并从原始组合新建（有未保存操作时明确提示）。
- 对比：同时展示原始与模拟的现金、持仓、市值、占比、行业集中度及提醒变化，不只给变化量。总资产应恒定。
- 方案：输入名字保存；列表显示方案名、时间、操作数。点击重开只读方案，明确标示已保存状态；可返回列表或新建草稿，不承诺修改或删除已保存方案。
- 加载状态避免重复提交；无操作时展示操作指引；无保存方案时显示空状态；输入错误贴近字段展示，网络/保存失败清晰展示且保留当前有效状态。切换到已保存方案也要防止静默丢失未保存草稿。

## 领域规则及精度
- 价格与现金从十进制字符串严格解析为整数“分”；中间金额使用安全整数并检查溢出。数量必须为正整数（拒绝字符串、布尔、NaN、无穷、零、负数、小数及不安全整数）。所有乘法/累加均验证安全整数，溢出请求返回明确错误。
- 总资产 = 全部市值 + 现金；现金计入占比分母，但不归入行业。
- 集中度使用整数交叉相乘或 BigInt 比较：单标的市值 × 100 > 总资产 × 30；行业市值 × 100 > 总资产 × 50。比较不使用展示值或浮点百分比；等于阈值不触发。金额和百分比展示两位小数。
- 从原始组合深拷贝，依序重放操作；所有操作使用相同 snapshot_id。买入检查现金，卖出检查当前模拟持仓。一次请求任一操作失败整次失败，不提交部分计算结果。前端仅在完整成功后接纳新的操作列表及结果。
- 固定价格、无费用情况下，模拟前后总资产不变。原始组合只读，任何模拟/保存均不能更新原始数据。
- 价格缺失、行业未知仅写明未来设计处理（禁止不完整估值；未知行业单列），不增加范围外功能。

## 数据与 API
原始 JSON 作为只读初始化文件；后端载入原始组合和快照。数据库保存方案 ID、名称、创建时间、原始组合及完整行情快照版本、顺序操作 JSON。重开时按方案保存的快照及原始组合重新计算，不依赖前端提交的金额或结果，也不被以后初始化文件变更影响。保存为一次事务；不另存可漂移的派生结果。当前草稿只驻留浏览器内存，未保存草稿刷新后不承诺恢复。

API：
- `GET /api/portfolio`：返回原始组合、快照、规则、完整估值及提醒。
- `POST /api/simulate`，`{operations: [{symbol, side: "buy"|"sell", quantity}]}`：返回原始与模拟结果、有效操作；无效返回 4xx 和错误位置/原因。
- `POST /api/plans`，`{name, operations}`：后端重新校验后保存，返回方案详情。空操作方案允许，名称去首尾空格后 1～60 字；可重名，以 ID 区分。为避免恶意或误操作限制单个方案最多 100 笔，超限给明确错误。
- `GET /api/plans`：方案概要列表，最新保存优先；`GET /api/plans/:id`：按持久化快照重放，返回只读详情，不存在返回 404。
- 统一错误结构 `{error: {code, message, operationIndex?}}`；JSON 格式错误、字段类型错误、超大请求、余额不足、持仓不足与保存失败分开处理。金额以十进制字符串传输，quantity 为整数，比例结果用于展示，是否超限以后端布尔判定为准。

```text
React 中文工作台 → Express API → 规则/模拟模块
                               ├─ 只读原始 JSON / 行情快照
                               └─ SQLite 方案库（原始快照 + 操作）
```

## 实现结构及取舍
建议 `client/` 前端，`server/` 规则、API 与存储，`shared/` 响应类型，`tests/` 规则与 API 测试，`data/` 初始 JSON，`docs/screenshots/` 证据。确切文件切分由实施者决定。
- SQLite 对比 JSON 文件：SQLite 原子写入和查询更直接，不需自建文件写入锁；以 Node.js 24 环境约束换取无额外数据库依赖。
- 保存快照+操作，对比仅保存结果：可复算和审计，防止不同快照混算；代价为少量冗余快照数据。
- 自写少量 CSS/基础图形，对比引入完整 UI/图表库：仅六只股票，表格与条形图已足够说明比例，降低安装和讲解负担。
